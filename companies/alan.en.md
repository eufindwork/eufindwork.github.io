## 4. Recruiting Process

Alan overall recruiting process for senior is ~33 days, internship relatively compressed. Main structure from Medium articles and official hiring page:

| Round | Content | Length | Format |
|---|---|---|---|
| 1. Screening | Bidirectional understanding, half the time candidate asks questions | 30 min | Video |
| 2. Technical Interview (CoderPad) | "**Not algorithm puzzle, not brain teasers**" — implement a small program close to daily work; shared editor (coderpad.io) | 60 min | Online (coderpad.io) |
| 3. Alaner Fit Interview | Founder/senior Alaner hosts; examines mission-driven mindset, growth mindset, communication, "take a step back" ability | 45 min | Video |
| 4. Checkpoint | Candidate feedback and question opportunity | Short | Async / Call |
| 5. Reference Calls | Candidate-provided references (Alan doesn't do back-channel checks) | Optional | Phone |
| 6. Alan Day | Half-day to full-day onsite (Paris) or video full set | 4-5 hours | Mix |

**Alan Day consists of 4 sub-interviews**:

| Alan Day Sub-round | Content | Length |
|---|---|---|
| **Past Project** | Choose a project you deeply participated in, talk about design/challenges/decisions/tech debt; examines communication + technical depth | 60 min |
| **Feature Design** | Given a new feature Alan might actually do, discuss how to design/break down/ship — like real brainstorm | 60 min |
| **Ask Me Anything** | Role reversal, candidate asks the company | 30 min |
| **Debrief** | Collect candidate's feedback on the process | 15+ min |

**Decision**: within **48 working hours max** after Alan Day for offer/rejection.

**Special notes** (important):
- **No take-home assignment** — Alan officially states no 6-7 hour take-home, because unfair/not inclusive
- Process is **structured**, detailed feedback given after each round (regardless of pass/fail)
- Uses interview scoring grid + multi-interviewer, borrowing FB/Google's unconscious bias training
- No algorithm puzzle, but feature design's "systems thinking" examination is deep

## 7. Culture, Work Environment, Soft Intel

Alan's engineering culture is one of the most distinctive in Paris area, key features:

- **No meeting** — async + written-down document-driven; in reality there's still some sync, but default is async
- **Salary fully transparent** — all can query each other's salaries; no negotiation, by level automatically set
- **No job titles** — no "Senior SDE I/II/III" tiers, just a few levels
- **Pair programming + code review** culture heavy, mentorship rigorous
- **Role buddy** system — each new hire (including intern) paired with a dedicated engineer for the first weeks/months
- **Rigorous hiring** — hard to get in, treated very seriously once in
- **Engineering principles**: written-down (on Medium by Charles Gorintin); emphasizes ownership, trust by default, async by default
- **Glassdoor 42% positive interview** — not high, but reputation is "challenging but human, transparent feedback"
- **Remote-friendly** — but intern generally leans toward Paris onsite for mentorship

## 8. Application Strategy & Timeline Advice

| Step | Advice |
|---|---|
| 1. Submit timing window | H1 2026 onwards stage **at the latest 10-11 month apply** (Alan internship rolling but quantity small, earlier the better) |
| 2. Mandatory preconditions | **Actually deploy full-stack app to production** — not hello-world, real users used it. This is the first thing the interviewer will ask |
| 3. CV focus | 1-2 end-to-end projects (Flask or FastAPI + React + Postgres, deployed to Vercel/Fly.io/Render), with GitHub + Live URL |
| 4. CoderPad prep | **Not LeetCode**. Practice real scenarios: "given a 5-file mini Flask app, find bug fix", "implement a simple CRUD endpoint" — use Python + existing framework, don't write from scratch |
| 5. Feature Design prep | Hypothetical: "How to design Alan's claim submission flow?" — user story → UI sketch → API design → DB schema → edge case → launch plan. Look at Alan public blog engineering articles |
| 6. Past Project prep | Choose **one** project to discuss deeply: why did it, design choices, your specific contribution, biggest tech debt, how to refactor afterward |
| 7. Alaner Fit | "Mission-driven" — think clearly why you're passionate about health/insurance. Clichés will be detected |
| 8. Prepare questions | Screening / AMA will both leave lots of time for candidate; prepare 10+ high quality questions (about culture, async, no-meeting in actual operation, mentorship) |
| 9. Alternatives | Same tier Paris health/insurance tech: Doctolib (bigger), Lifen, Qare, Withings; same tier fast-growing startup: ContentSquare, Datadog, Mirakl, Aircall, Spendesk |
